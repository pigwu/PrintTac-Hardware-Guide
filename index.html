Tools you will need

02

3D PRINTING

Print the structural parts

COMPLIANT STRUCTURE

PETG flexure

The monolithic flexure allows the contact plate to move relative to the fixed magnetometer array. Print both fingers from the same CAD model and print profile to reduce fabrication differences.

CONTACT GEOMETRY

PLA contact tip

The rigid contact tip is mechanically separate from the sensing core. Change the task-facing geometry while preserving the relative positions of the magnets, sensor board, and flexure.

Print parameterAvailable specification
MaterialPETG for the compliant flexure; PLA for the rigid contact tip.
Layer height, walls, infill & orientationPending a validated print profile. Do not treat these as interchangeable settings.
Nozzle, temperature, speed & supportsPending a profile matched to the printer and filament.
Revision trackingRecord the CAD revision, filament batch, and slicer project. Keep both fingers consistent.

Inspect each print

  • Check the flexure beams for cracks, layer separation, and remaining support material.
  • Verify that the contact plate, magnet pockets, and sensor-board mounts match the CAD.
  • Apply a gentle load and check elastic return. Moving parts must not collide with the electronics.

These are suggested assembly checks. Load limits and dimensional tolerances must come from the matching design revision; simulation loads are not a rated operating limit.

03

FINGERTIP ASSEMBLY

Assemble the tactile fingertips

  1. Confirm the magnet layout

    Follow the matching CAD for pocket positions, magnet count, and polarity. Keep both fingers consistent with the reference sensing configuration. Confirm polarity before permanently securing the magnets.

  2. Mount the sensor board and flexure

    Keep the magnetometer board fixed to the base while the magnets move with the contact plate. Check that tightening does not bend the board or constrain the flexure. Route cables clear of moving parts.

  3. Attach the replaceable contact tip

    Use the fasteners specified by the design. Preserve the internal magnetic sensing stack when replacing a tip. Check the unloaded signal and elastic return after assembly and each replacement.

  4. Validate one finger, then assemble the pair

    Gently touch the tip and inspect all five chips. Signals should respond to contact and return to a stable unloaded baseline. Once both fingers pass, mount them on the gripper and secure the phone and cables.

04

POWER & WIRELESS

Power and connect the sensors

!
Verify the board documentation before wiring

The available materials do not establish the exact sensor-board pinout, voltage, or bus wiring. Obtain the sensor-board documentation, QT Py ESP32-S3 (5426) documentation, power requirements, and matching firmware first. In this architecture, USB-C supplies power; magnetic data travels over Wi-Fi.

  1. On the iPhone, enable Personal Hotspot and Allow Others to Join.
  2. For 2.4 GHz boards, enable Maximize Compatibility. Prefer ASCII characters for the phone name and hotspot password.
  3. Configure the hotspot SSID and password in the matching firmware. Assign separate ports to the right and left fingers.
  4. After connecting, read the gateway address from DHCP and send packets to that address. Do not hard-code the phone IP.
  5. Open the app and inspect each side's receive rate, packet loss, sequence number, and five-chip readings.

06

GRIPPER CALIBRATION

Calibrate the gripper aperture

Sensor-instance consistency and aperture calibration are separate concerns. The current software estimates opening from two ArUco markers in the ultrawide image. After assembly, calibrate this measurement against the actual distance between the inner gripping surfaces.

Marker dictionaryDICT_4X4_50
Marker IDs0 and 1
Black outer edge16 mm

  1. Print, measure, and mount the markers

    Print at 100% scale and verify the black outer edge with calipers. Rigidly mount IDs 0 and 1 on the moving jaws. Keep them at similar height and depth, approximately coplanar, with the camera X axis aligned to the opening direction.

  2. Open the ultrawide monitor

    Launch desktop/experiment_replay_ui.py using the commands below. Services start automatically; if stopped, select Start Monitor. Open ArUco Gripper. Both markers must be visible in the same 0.5× frame throughout the opening range.

  3. Record the minimum and maximum openings

    Measure the actual jaw gap with calipers. Hold the minimum opening still for about one second and record the minimum point. Repeat at the maximum opening.

  4. Save and check an intermediate opening

    Save and apply the calibration. Compare an intermediate opening against the calipers. Recalibrate after changing marker placement, print scale, camera lens, or mounting geometry.

Use Python 3.10 or newer. Replace PHONE_IP with the iPhone's actual IP; on its hotspot, this is the computer's default gateway (commonly 172.20.10.1). On macOS, replace py with python3. Run these commands from the collection repository. Keep this window open for calibration, capture, upload, and replay.

Measurement model and depth gate

The raw measurement is the separation of the two markers along the camera X axis in the same frame:

raw_width = abs(x_id1 - x_id0)
opening = scale × raw_width + offset

The default marker-depth gate is 72 ± 8 mm. If the monitor reports marker_depth_out_of_range, use its control to apply the current depth. The quick calibration uses statistics from stable frames; repeated opening and closing remains an optional robust-calibration method.

07

FIRST CAPTURE

Record your first demonstration

Use experiment_replay_ui.py as the main experiment workspace. It combines live monitoring, remote recording controls, upload reception, and synchronized replay. The iPhone records the original data locally and uploads the saved experiment to the computer.

  1. Connect the phone, sensors, and computer

    Enable the iPhone hotspot and connect both sensor boards and the computer. Open the iPhone app, set its host address to the computer's actual IP, and enable live streaming. Confirm normal ARKit tracking and enable the video recording options needed for the experiment.

  2. Check the experiment workspace

    Launch the UI with the commands above. Confirm Upload storage: READY and Phone ready; capture is idle. Check both magnetic streams, the 1× preview, and the 0.5× ArUco view. The monitor includes the upload server on TCP 8000 and the live receivers; run one listener per port.

  3. Start a synchronized experiment

    Under Phone Experiment Capture, select Start Experiment and wait for the phone's recording confirmation. Move the phone, gently touch each fingertip, and open and close the gripper during a short test.

  4. Stop, save, and finish uploading

    Select Stop & Save Experiment. Keep the app and monitor open while the phone saves and uploads. In Experiment Replay, select the experiment and check Phone Upload Files for Complete phone upload. If transfer is incomplete, use the iPhone's Past Records upload controls to resend the missing data or video.

  5. Replay and validate the result

    Inspect saved video, pose, both tactile streams, and gripper aperture together in Experiment Replay. After a complete upload, the monitor queues dataset.zarr export and, when an ultrawide video is available, offline processing for aruco_gripper.csv. Check processing status before using those outputs.

Check uploads and processing separately

Source runs save experiments under uploads/ at the collection repository root. Magnetic CSVs require samples from the corresponding board; videos require recording to be enabled on a supported device.

aruco_gripper.csv and dataset.zarr are desktop processing outputs. Wait for their jobs to finish. For two-finger experiments, confirm both magnetic files are present and replay the short test before collecting a longer demonstration.

Collect without a connected computer

The iPhone can record locally while away from the computer. Use its Start Experiment and Stop & Save Experiment controls. Later, reconnect to the computer, start the experiment UI, and upload the saved session from Past Records for replay and processing.

08

VALIDATION & TROUBLESHOOTING

Validate before collecting data

Pre-capture checklist

  • Unloaded magnetic readings are stable and respond reproducibly to touch and release.
  • Left and right channels match the physical fingers. Sequences increase, and receive rate and packet loss have been checked.
  • Both ArUco markers remain visible, and an intermediate opening agrees with the caliper measurement.
  • Pose changes reasonably with phone motion, and the session contains the expected data and videos.
  • A test session uploads successfully and can be opened or replayed on the computer.
The boards connect to the hotspot, but no magnetic data arrives

Check 2.4 GHz compatibility, local-network permission, the DHCP gateway, side-specific ports, and the ASKN packet format. The current app expects 96-byte packets. Firmware must implement the matching protocol. Enable the hotspot before starting or reconnecting the boards.

Only one finger appears, or the fingers are swapped

Touch each finger separately and check the corresponding app channel. The right finger uses UDP 5557; the left uses UDP 5562. Configure both boards independently. Sending both streams to one port does not automatically separate the sides.

The ArUco opening is unstable or calibration fails

Confirm the monitor is processing the 0.5× stream, both markers are visible in the same frame, the printed size is 16 mm, and marker depths pass the gate. Avoid warped or reflective markers. Hold each endpoint still for about one second and repeat if there are too few valid frames.

The magnetic baseline changes after replacing a tip

Check whether the magnets, sensor board, or flexure moved, whether tightening caused deformation, and whether nearby magnetic objects affect the signal. Resolve mechanical and environmental changes before repeating the unloaded check.

The desktop Start Experiment button is disabled

Confirm the monitor is running, Phone IP points to the iPhone, and the app is open. The button becomes available after the phone acknowledges that capture is idle. If no recording-control reply arrives, check the network and use matching current app and desktop versions.

Recording works, but upload fails

Check Upload storage: READY in the experiment UI, the app's Host IP, and access to TCP 8000 through the firewall. If the port is already in use, stop any separate upload server before restarting the monitor. Use Past Records to resend missing data or video, then verify Complete phone upload in the replay tab.
